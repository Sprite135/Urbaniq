# Urbaniq — Estado del proyecto

## Objetivo
Transformar Urbaniq de tienda de ropa a e-commerce de informática (es-PE), con catálogo real de computación y sin rastros de ropa en UI ni datos.

## Detalles clave
- Backend .NET 8 en puerto **5215**, sirve `Frontend/dist` desde `Backend/Ecommerce.Api/wwwroot`. DB = **EcommerceDb** en `(localdb)\mssqllocaldb`.
- 16 categorías, 96 productos. Todos los productos Y todas las categorías tienen imágenes reales en `/uploads/products/`. (32 originales + 32 de catálogos reales + 32 añadidos vía 4 subagentes que descargaron imágenes reales a `wwwroot/uploads/products/` e INSERT SQL en Products+ProductVariants+ProductImages. Flujo reproducible: JSON de productos -> `gen_products.ps1` genera/inserta SQL con slugs únicos.)
- **Stripe NO configurado → modo demo**: `GET /api/v1/Payment/config` requiere auth y devuelve 409 sin publishableKey. El checkout funciona en demo (tarjeta simulada sin cargo real, `CARD_DEMO_<ts>`); si Stripe tuviera claves, se usa el flujo real (Elements+PaymentIntent+verify). Funcionan siempre: cod, yape, plin, bcp, interbank, bbva, scotiabank, pagoefectivo. Yape NO llama Stripe.
- **Delivery estilo Memory Kings** (zonas Perú, SIN pincode indio): `Address` usa `PostalCode`(opcional)/Department/Province/District/Reference/DeliveryZone; `LimaMetropolitana` = siguiente día (24h, o 24-48h si `RequiresConfiguration`), `Provincias` = vía Shalom/Marvisur contra entrega (92% cobertura). `OrderService.EnsureAddressCanReceiveCart` ya no valida pincode. Teléfono normalizado a **+51** (peruano) en `AuthService.NormalizePhoneNumber` (antes +91 indio). Propiedades renombradas: `Address.Pincode→PostalCode`, `Address.PostOffice→Reference`, `Product.DeliverablePincodes→DeliverableZones`, `CartItem.DeliveryPincode→DeliveryCode` (+ columnas BD renombradas vía sp_rename). Parser `ProductOptionParser` métodos renombrados a `ParseDeliveryCodes`/`NormalizeDeliveryCodes`.
- Quirks shell: `curl.exe`, `cmd /c`, `sqlcmd -f 65001`, `-o nul`. `Stop-Process` + `dotnet run --launch-profile http` para reiniciar backend (limpia caché de árbol de categorías de 10 min).
- Registro/login acepta **cualquier correo** (se relajó la regla `@gmail.com` en `RegisterRequestValidator` y `LoginRequestValidator`). Contraseña: mín 8, mayúscula, minúscula, dígito. `AuthResponseDto.accessToken` (minúscula). Teléfono dirección debe ser 10 dígitos (normalizado a +51).
- Test data válido: ProductId `75A59A5B-187F-49E8-B6E0-4051B3366B9D`, VariantId `EA3B3C4C-09F2-4F0B-B035-06343567102E`. Zonas de entrega opcionales (Perú).
